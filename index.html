Problem 1　Approach 1

Annotated image: one pass

Brush-editing an image also changed the unbrushed areas.

  1. Provide both images: the original, and the same image with annotation boxes drawn on
  2. State what each box type does, and that the boxes must not appear in the result
  3. For a transparent base, set the background parameter to transparent
Limits
  • Done in one pass: both marked splashes deleted, the baseball completed
  • The whole image is repainted: unmarked elements are similar, not pixel-identical
  • With text alone and no annotated image, edit placement is unstable
Bad-case hands-on11
Problem 1　Approach 2

Layered: pixel-level edits

Required: untouched areas keep every pixel.

  1. Layer separation: split into 5 layers, front to back
  2. Delete: drop the two milk-splash layers outright
  3. Edit: send only the baseball layer, make it a true sphere
  4. Recomposite: stack in original order; outside the edit, original pixels are kept
Limits
  • 96.8% of pixels identical to the original; zero pixels changed outside the edit area
  • Occluded areas are filled in by the model — newly generated content
  • Needs one local composite step — not a single generation

Problem 3　Product swap

Swap only the product, everything else untouched

Once the video is approved, swap only the product — person, action, camera and style stay.

  1. First prepare the new product reference: pure white background, one product only, the to-camera face showing.
  2. Write “replace only X with Image 1”, and state which features each visible face must show.
  3. List everything that must not change: person, outfit, background, action order, camera moves.
Limits
  • This direct edit swapped the product in one generation — both phones, strongly different colours. Judged from sampled frames, not checked frame by frame.
  • Swapping the same video to another black phone earlier could not be confirmed — when old and new look alike, success is hard to judge.
  • Very different shapes, brand marks and small print are untested — no guarantee they map one-to-one.

Problem 3　Multilingual versions

One character image, four language versions

Same character image, same prompt — only the VO and line change.

  1. The character image as reference locks character, outfit and scene
  2. That language's VO as the reference audio
  3. The prompt states: speak this line with this audio, mouth follows the audio, all else unchanged
  4. Duration rounds up to the VO length
Limits
  • Every video is regenerated; action and background details won't match frame-for-frame across versions
  • All four are single takes, uncurated; lip-audio alignment was not measured — review each by eye
  • The final's audio is re-rendered by the model from the VO, so pauses don't match exactly; the language and lines actually spoken in each version are untranscribed — listen to each one
  • This example is a cartoon character; references that look like real people are rejected

Problem 5

Likenesses and copyrighted characters: the platform blocks, the user still reviews

Digital humans may resemble real people or copyrighted characters — does the platform review for this?

1

Blocking already in place

For real-person lookalikes and copyrighted characters, one layer of blocking is already in place.

2

Blocking backed by an IP library

Blocking runs on an IP library, so it cannot catch every IP and copyrighted work. No model or vendor on the market can block them all.

3

The user side owns review and control

No model or platform can fully guarantee non-infringement — final review and control sit with the user.

Problem 8

UI placed on a device screen

Compositing product UI onto a device tends to warp perspective and garble text — expensive to reroll.

  1. Match the UI image's aspect ratio to the device screen — portrait UI on portrait devices.
  2. The prompt states the UI fills the screen in its original layout — no re-flow.
  3. List every piece of UI text in the prompt, line by line.
Limits
  • When UI and screen ratios disagree, layouts re-flow and text garbles — switch to post-production tracking instead.
  • The demo uses our generated example UI, not a client's real product UI.
  • Each generated once, camera square to the screen; steep angles untested.

High-consistency production

The 3D clay model locks space and motion, keyframes lock the picture, and Seedance renders to both.

Camera position, focal length and lighting cannot be locked by prompt and references alone

  • ControlReferences lock subject and style; camera, focal length and lighting remain text-described — approximate, not locked.
  • ConsistencyFine within one shot; across shots and angles the product deforms — generative models hold no explicit 3D geometry.
  • VariantsEach variant is regenerated; every batch differs slightly.
When text and plain references aren't precise enough, upgrade the control tools
For plot order, storyboards; for exact composition, keyframes; for complex motion, clay models; for spatial occlusion, depth video.

Case 1

A car shot, from clay model to final

The shot demands exact camera paths, vehicle lines, scale and occlusion — previz in clay first.

  1. Build the main space to real scale, drop in a proxy vehicle, mark ground, obstacles and the motion envelope.
  2. Set camera height, focal length, start/end and path; sanity-check perspective and framing with a few keyframes first.
  3. Add subject motion and occlusion, output the previz; check for clipping, exits and rushed pacing.
  4. Provide the clay-model video plus look and scene references; generate the final.
  5. Final checked against previz at the start, midpoint, occlusions, contact points and end framing.

Lock composition with standalone keyframes

  • Keyframes lock the key compositions — opening, turn and ending.
  • Separate keyframes align far more strictly than one grid sheet.
  • Keyframes must share continuous spatial relationships and action logic.
  • A grid storyboard gives plot and shot order only, with no per-cell alignment guarantee; keep it under 15 cells.
